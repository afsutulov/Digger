# Digger Game

[English (default)](README.md)

Нативный перенос Digger на Go для Windows, Linux и macOS. Игровые правила,
спрайты, шрифт, планы уровней и таблицы музыки перенесены из реконструкции
Digger Remastered и её Java-версии, затем сверены с приложенным DIGGER.COM.
DOSBox, Java и исходный COM для запуска этой игры не нужны.

## Сборка из исходников

Нужен **Go 1.24 или новее**. Все Go-зависимости включены в `vendor`, поэтому
при сборке их не нужно загружать из сети. Основной файл — `main.go` в корне.

Windows (PowerShell / cmd):

```text
go build -mod=vendor -buildvcs=false -ldflags="-s -w -H=windowsgui" -o digger.exe .
```

Linux (пример для Debian/Ubuntu):

```sh
sudo apt-get install build-essential pkg-config libx11-dev libxi-dev \
  libxrandr-dev libxcursor-dev libxinerama-dev libxxf86vm-dev \
  libgl1-mesa-dev libasound2-dev
go build -mod=vendor -buildvcs=false -o digger .
./digger
```

macOS: установить инструменты разработчика Apple и собрать **на самом Mac**:

```sh
xcode-select --install
go build -mod=vendor -buildvcs=false -o digger .
./digger
```

В Linux и macOS оставить CGO включённым. Графический и звуковой backend
Ebitengine использует системные библиотеки. Игровые правила написаны на Go.

## Иконка и сборка с её встраиванием

Новая иконка выполнена в стиле пиксельной графики: зелёный Digger и изумруд.
В корне проекта находятся:

* `digger.png` — изображение, встроенное в Go-код директивой `//go:embed` в
  `main.go`. Оно передаётся в `ebiten.SetWindowIcon`; отдельный PNG рядом с
  готовой игрой не нужен. Отображение зависит от рабочего стола; на macOS
  Ebitengine не поддерживает эту функцию.
* `digger.ico` — Windows-иконка с размерами 16, 24, 32, 48, 64, 128 и 256 пикселей.
* `icon_windows_amd64.syso` и `icon_windows_arm64.syso` — готовые ресурсы для
  встраивания ICO в `.exe`. Go автоматически выбирает файл по целевой платформе
  и архитектуре. Благодаря этому иконка доступна Проводнику Windows.

**Сборка с уже включённой иконкой** из корня проекта на Windows
(PowerShell / cmd) не требует дополнительных инструментов или доступа к сети:

```text
go build -mod=vendor -buildvcs=false -ldflags="-s -w -H=windowsgui" -o digger.exe .
```

**Чтобы изменить иконку**, замените `digger.png` квадратным PNG, а `digger.ico` —
многоразмерным ICO. Затем пересоздайте оба `.syso` и соберите игру. Для этого
однократно установите [rsrc](https://github.com/akavel/rsrc) указанной версии
(установка требует сети). Каталог Go с исполняемыми файлами, обычно
`GOPATH/bin`, должен быть в `PATH`:

```text
go install github.com/akavel/rsrc@v0.10.2
rsrc -ico digger.ico -arch amd64 -o icon_windows_amd64.syso
rsrc -ico digger.ico -arch arm64 -o icon_windows_arm64.syso
go build -mod=vendor -buildvcs=false -ldflags="-s -w -H=windowsgui" -o digger.exe .
```

Сохраните суффиксы платформы и архитектуры в именах `.syso`. Не добавляйте
рядом общий `rsrc.syso`: это создаст дублирующиеся ресурсы. Поддержка ARM64
в rsrc помечена экспериментальной; ресурс из архива проверен в собранном PE.

Кросс-компиляция Windows-версий из Linux/macOS (команды для `sh`):

```sh
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -mod=vendor -buildvcs=false -ldflags='-s -w -H=windowsgui' -o digger-x64.exe .
GOOS=windows GOARCH=arm64 CGO_ENABLED=0 go build -mod=vendor -buildvcs=false -ldflags='-s -w -H=windowsgui' -o digger-arm64.exe .
```

При сборке Linux/macOS обычными командами выше PNG также включается в бинарный
файл. Для иконки Finder на macOS нужен пакет `.app` с `.icns` и `Info.plist`;
отдельный исполняемый файл такой иконки не задаёт.

## Управление

| Клавиша | Действие |
| --- | --- |
| Enter / обычная печатная клавиша | Начать игру на заставке |
| Esc на заставке | Один / два игрока |
| Стрелки / 8, 2, 4, 6 цифрового блока | Движение |
| F1 | Выстрел |
| Пробел | Пауза; следующая клавиша продолжает игру |
| F7 | Музыка |
| F9 | Весь звук |
| F10 | Вернуться на заставку |
| + / − | Ускорить / замедлить игру |
| Alt+Enter | Полный экран |
| Закрыть окно | Выход |

Два игрока играют **по очереди**, как в оригинале; их уровни, туннели, мешки,
изумруды, очки и жизни сохраняются отдельно. Поддерживаются контроллеры с
распознаваемой стандартной раскладкой: левый стик / крестовина — движение,
нижняя правая кнопка — выстрел, Start — начало. Физический контроллер не тестировался.

## Что сохранено

* Все восемь оригинальных планов и последовательность их повторения до уровня 1000.
* Пиксельная сетка движения: 4 пикселя горизонтально, 3 вертикально.
* Nobbin / Hobbin, смена поведения, появление монстров, охота и столкновения.
* Толкание, раскачивание и падение мешков, раздавливание, превращение в золото.
* Изумруды, серия из восьми с дополнительными очками, бонус и удвоение награды.
* Выстрел, перезарядка, столкновения с препятствиями и анимация взрыва.
* Анимации смерти, завершение уровня, три начальные жизни и дополнительные жизни.
* Особенность второго игрока: дополнительная жизнь после превышения 20 000,
  тогда как первый получает её при достижении порога.
* CGA-графика 320×200, исходный шрифт, заставка и демонстрация персонажей.
* Музыкальные таблицы и эффекты PC Speaker, синтезируемые на современном аудиоустройстве.
* Ввод и сохранение десяти рекордов; исходная таблица из вашего HSC встроена в игру.

По умолчанию окно имеет пропорции 4:3, как экран старого CRT. Масштабирование
без сглаживания. `--square-pixels` включает пропорции 320:200.

## Параметры

```sh
./digger --fullscreen
./digger --speed 80 --players 2
./digger --square-pixels --mute
./digger --level 8 --seed 12345
./digger --data-dir ./my-data
./digger --import-hsc /path/to/DIGGER.HSC
```

`--speed` — длительность игрового кадра в миллисекундах, 40–200; по умолчанию 80.
Скорость не зависит от производительности процессора. В оригинале воспринимаемый
темп зависел от оборудования, поэтому настройка оставлена доступной.
`--import-hsc` заменяет сохранённую таблицу рекордов перед запуском.

Рекорды и настройки лежат в пользовательском каталоге конфигурации:
Windows `%AppData%\Digger-Go`, Linux `~/.config/Digger-Go`,
macOS `~/Library/Application Support/Digger-Go`.
Файлы: `scores.json`, `settings.json`. Последняя выбранная скорость сохраняется.

## Проверки и точность

```sh
go test -race ./internal/game
go vet ./internal/game
```

Пройдены проверки запуска восьми уровней, движения, паузы, начисления жизней,
рекордов, импорта HSC, генератора случайных чисел, повторения уровней и
6000 игровых кадров по сценарию с двумя игроками. Есть проверка CGA-изображения
по снимку **именно приложенного COM**, запущенного в DOSBox: статичные пиксели
первого уровня совпадают. Два прямоугольника движущихся персонажей из этой
проверки исключены, поскольку снимки сделаны в разные моменты.

Это нативный перенос, но полная покадровая эквивалентность каждого сценария
DOS-программе не доказана. Синтез звука воспроизводит ноты и эффекты, однако
аналоговое звучание старого PC Speaker и точные аппаратные задержки могут
отличаться. macOS, реальное Windows-окно и физический контроллер требуют
проверки на соответствующем оборудовании.

## Устройство кода

* `main.go` — окно, клавиатура, контроллер, вывод изображения и аудиопоток.
* `internal/game/runtime.go` — независимый игровой цикл, синтез звука и рекорды.
* `digger.go`, `monster.go`, `bags.go`, `main.go` — игровые алгоритмы.
* `drawing.go`, `spriteengine.go`, `cgadisplay.go` — исходная CGA-отрисовка и коллизии.
* `cgagrafx.go`, `alphabet.go`, `sound.go` — графические и музыкальные данные.
